# Retail Algorithmic Trading Safety Invariants

## Invariant 1: Compile-Time & Runtime Live Trading Lock
- Code located at `execution/live_broker_disabled.py`
- Instantiating `LiveTradingPermanentlyDisabledBroker` raises `RuntimeError`.
- Any broker adapter (Dhan, Zerodha) intercepts `place_order` and raises `RuntimeError` unless execution mode is explicitly paper trading.

## Invariant 2: NSE NIFTY Lot Size of 65
- Enforced across `config.py`, `market_data/instruments.py`, `risk/limits.py`, and `risk/engine.py`.
- Any order quantity that is not a multiple of 65 is instantly rejected with `REJECT_LOT_SIZE`.
- In V1, the maximum permitted position size is 1 lot (65 units).

## Invariant 3: ₹3,000 Capital Feasibility Filter
- Arbitrage strategies (Put-Call Parity, Box Spreads, Reversals, Conversions) require short option or future positions.
- Shorting requires NSE SPAN margins of ~₹1,20,000 to ₹1,50,000 per lot.
- Any signal generated by an arbitrage scanner is flagged `is_capital_feasible = False` and tagged `CAPITAL_INFEASIBLE`.
- The Order Management System (OMS) rejects routing any infeasible signal to execution.

## Invariant 4: Maximum Loss Per Trade (₹150.00)
- The pre-trade risk engine computes potential loss including round-trip statutory friction.
- If $Loss_{\text{points}} \times 65 + Fees_{\text{roundtrip}} > 150.00$, the order is rejected.

## Invariant 5: Daily Loss Limit (₹300.00) & Capital Floor (₹2,000.00)
- If realized loss reaches ₹300.00 (10% of initial ₹3,000 capital), the emergency kill switch is engaged automatically.
- If cash drops below ₹2,000.00, all further orders are rejected.

## Invariant 6: Quote Staleness Ceiling (1,500ms)
- Ticks and orderbooks older than 1,500ms trigger `STALE_DATA_HALT`.
